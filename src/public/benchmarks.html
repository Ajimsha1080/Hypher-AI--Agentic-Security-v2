Methodology

Test environment

AWS t3.small (2 vCPU, 2GB RAM), us-east-1. Postgres on RDS db.t3.micro. Redis on ElastiCache cache.t3.micro. All in the same VPC — no network egress overhead. MOCK_UPSTREAM=true for the MCP server response (MCP server latency is not included — we measure gateway overhead only, same methodology as Bifrost).

500 iterations per scenario. 20-request warmup discarded. Results are median of 3 runs.

What each scenario measures

Warm cache: tenant config and registry trust loaded from Redis. Represents steady-state after the first few requests.

Cold cache: every layer queries Postgres. Happens on first request or after Redis flush. Not representative of production steady-state.

DLP triggered: response scanning with 25 PII regex patterns applied to a 200-byte response. Scales with response size and pattern count.

Run it yourself

The benchmark tool is open source and ships with the gateway:

GATEWAY_URL=http://localhost:3000 BENCHMARK_TOKEN=your-token npm run benchmark

Results saved to benchmark-results.json. Methodology is reproducible — PRs to improve it are welcome.
